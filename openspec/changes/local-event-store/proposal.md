# Proposal

## Why

第 1 期已交付可校验的 `HealthEvent` 契约，但事件目前只能存在于内存中。没有持久层，第 3 期的实体映射无处落地，第 4 期的导出无数据源，而"重复写入是否只保留一条""删除后是否真的消失""重启或崩溃后是否完整"这些正确性问题都无法被验证。第 2 期在不依赖 HA 实体、不引入任何外部服务的前提下，先把事件持久化的可靠性证明出来。

## What Changes

- 新增本地事件存储：SQLite（Python 标准库 `sqlite3`），单数据库文件，无 ORM、无独立服务。
- 新增事件表与索引列（事件 ID、测量者、顶层指标、观察起止瞬时键、精度、修正引用、取代标记），规范事件整体保留为 `payload_json`。
- 新增幂等写入：以 `eventId` 数据库唯一约束为最终保障，重复提交只保留一行并返回"已存在"而不是新增。
- 新增修正链：用户修正产生新事件并通过 `correctionOf` 指向旧事件；旧事件保留可按 ID 检索，默认查询返回当前有效版本。
- 新增查询接口：按测量者、指标、时间范围过滤，分页与稳定排序，支持包含/排除被修正版本。
- 新增用户删除：按事件 ID 批量删除，删除后本地查询与后续导出无法恢复其内容；修正引用随删除置空，不级联删除其他事件。
- 新增数据库迁移：基于 `PRAGMA user_version` 的顺序迁移，失败时拒绝进入写入状态，重复启动幂等。
- 新增备份与恢复：使用 SQLite Backup API 生成一致性快照；恢复后执行完整性、外键与业务不变量检查。
- 新增异步包装：同步数据库操作经线程卸载，写操作串行化，保证不阻塞调用方事件循环。
- 新增存储层测试矩阵：幂等、事务回滚、并发写、修正链、删除、逐版本迁移、备份恢复、事件循环不阻塞。

## Capabilities

### New Capabilities

- `health-event-store`: 健康事件的本地持久化能力——幂等写入、修正链与有效版本、按测量者/指标/时间查询、内容删除、版本化迁移、一致性备份与恢复、非阻塞访问。

### Modified Capabilities

（无——`health-event` 契约的字段、校验与身份规则不变；存储层只是消费者。）

## Impact

- 新增代码：`custom_components/openhealthrouter/store.py`（SQL、事务、查询）、`migrations.py`（版本化迁移）、`async_store.py`（线程卸载与写串行化）。
- 新增数据：运行时数据库文件位于 HA 配置目录下 `openhealthrouter/events.db`（由第 3 期接入时提供路径；本期接受显式路径以便测试）。
- 新增测试：`tests/storage/` 覆盖幂等、回滚、并发、修正链、删除、迁移、备份恢复、非阻塞。
- 依赖：不新增第三方依赖（仅标准库 `sqlite3`、`asyncio`、`shutil`）。
- 破坏性：无（尚无数据库存在；schema 从 `user_version = 1` 起）。
- 阻塞后续：第 3 期实体接入与第 4 期导出都依赖本存储。
- 需人工审批：删除语义、迁移规则与备份边界（roadmap 第 2 期明确要求）。
