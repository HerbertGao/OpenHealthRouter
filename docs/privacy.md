# 隐私与安全

健康数据路由的信任边界不只是“使用 HTTPS”。系统必须限制什么数据被保存、谁能读取、哪些字段可以离开本机，并让用户能够检查和撤销这些决定。

## 1. 默认原则

- 本地优先，事件首先持久化在用户自己的 HA 主机。
- 默认不自动向外部 AI、厂商云或 Webhook 持续发送数据。
- 只读取用户明确配置的 HA 实体，不批量复制 HA 数据库。
- 导出按目标、指标、时间范围和数据层级最小化。
- 原始属性、设备信息、备注和未来原始文件默认不外发。
- 外部消费者不能直连 SQLite 或任意遍历 HA State。
- 日志和审计默认不包含健康值、完整请求体或密钥。

## 2. 数据分类与默认策略

| 数据 | 本地保存 | 默认导出 |
| --- | --- | --- |
| 规范健康事件 | 是 | 仅用户选择后 |
| 原始实体属性 | 仅映射所需及追溯所需 | 否 |
| 测量者与设备标识 | 使用本地引用 | 否，除非用户明确包含 |
| 备注和测量上下文 | 按指标需要 | 否，除非用户明确包含 |
| Webhook 密钥 | 使用 HA 凭据机制 | 永不 |
| 导出审计 | 保留必要元数据 | 不属于健康数据导出内容 |
| OCR 图片、PDF 等原始文件 | 首版不支持 | 未来默认仅本地 |

本地测量者引用应使用随机或内部 ID，不把姓名、生日、手机号直接放进 `subjectRef`。真实身份与本地引用的对应关系留在本地配置中。

## 3. 用户确认与导出范围

每次手动导出至少展示：

- 目标及目标地址；
- 指标集合；
- 起止时间和实际事件数量；
- 是否包含质量问题事件、修正前事件或厂商派生值；
- 是否包含原始属性、设备信息或备注；
- 发送后目标可能承担的保留责任。

默认导出规范事件的当前有效版本，不包含原始属性、被修正旧版本和未选指标。过滤必须发生在序列化和网络请求之前，不能“先发送完整包，再让接收方筛选”。

撤销某个目标的授权只阻止后续导出，不能假定远程服务已经删除历史数据。UI 必须明确这一边界。

## 4. Webhook 安全

首版 Webhook 是用户确认后的显式导出：

- 远程目标使用 HTTPS 并验证证书；不得默认提供忽略 TLS 验证的开关。
- 密钥不出现在 URL、事件、审计或日志中。
- 请求带时间戳、唯一投递 ID 和基于原始请求体的 HMAC-SHA256 签名；密钥通过 HA 凭据机制配置。
- 接收方应校验时间窗口并拒绝重复投递 ID，降低重放风险。
- 请求设置有限超时，失败不向用户显示成功。
- 健康事件写入与网络投递解耦；外部不可用不能造成本地数据丢失。
- 首版由用户明确重试，不创建默认后台持续同步任务。

具体签名头和 canonicalization 规则应随实现形成独立契约及测试向量，不能由发送方和接收方各自猜测。

## 5. 审计与日志

导出审计至少记录：本地时间、目标本地引用、过滤条件摘要、事件 ID、投递 ID、成功或失败类别。不得记录完整健康载荷、认证头或可复用签名。

诊断日志可以使用实体 ID、映射 ID、事件 ID 和错误码定位问题。健康值、原始属性、请求体和密钥不得进入默认日志；用户主动生成诊断包时，也必须先展示并允许移除敏感字段。

## 6. 删除、保留与备份

- 默认不按照 HA Recorder 的保留期删除健康事件，也不设置静默条数上限。
- 用户可以删除所选事件及其原始属性；关联导出记录只保留必要操作元数据。
- 修正链中的事件被删除时，应同时处理指向它的引用，不能留下可恢复已删除内容的副本。
- HA 备份可能包含 SQLite 数据库、映射和证据，因此备份文件本身也必须按健康敏感数据保护。
- 删除本机数据不代表已删除 HA 备份、用户导出的 NDJSON 或远程 Webhook 已接收的数据；界面应逐项说明。

未来加入保留期或归档功能时，必须在执行前展示范围并提供可恢复备份，不能静默淘汰。

## 7. AI 与未来外部服务

AI 是可选消费者，不是数据库管理员。未来提供 MCP 或 AI 查询工具时：

- 使用只读、参数化查询，按授权限制指标和时间窗口；
- 默认返回摘要及证据事件 ID，不直接开放完整数据库；
- 趋势结论必须附数据窗口、样本数、覆盖率和证据引用；
- 数据不足、来源被撤销和没有数据必须区别表达；
- 医学提醒由经过验证的确定性规则产生，AI 只负责解释，不自行发明阈值；
- 外部提示词、Webhook 响应和导入文件都视为不可信输入，不能改变本地权限或触发未确认导出。

## 8. 首版安全检查

1. 新安装且未配置导出目标时，没有健康数据外发请求。
2. 日志、审计和异常堆栈中找不到健康值与 Webhook 密钥。
3. 导出最近 3 天体重时，不包含其他日期、指标或原始属性。
4. Webhook 签名错误、超时或重复投递不会绕过接收方校验或造成重复计数。
5. 删除事件后，本地查询和后续导出均不能恢复其内容。
6. HA 备份和导出文件的敏感性与远程删除边界在 UI 中有明确说明。

## 9. 导出与投递（第 4 期）

**数据落点**：事件库 `config/openhealthrouter/events.db`（含投递审计表 `deliveries`）；Webhook 目标（名称、URL、密钥）保存在集成的配置条目里。

**备份范围**：HA 备份会包含事件库与配置条目，因此备份文件本身等同于健康数据与密钥。恢复后投递审计仍在；密钥也随之恢复，轮换密钥需要重新配置目标。

**导出默认面**：默认只导出 `valid` 状态的规范事件，且默认剔除设备引用、测量者标识、测量上下文与原始属性（`docs/privacy.md` §2 的"默认否"）。需要区分对象时必须显式打开对应开关，预览会显示四项开关的实际取值、生效的质量状态、厂商派生值与质量问题的条数，以及"被修正旧版本默认不导出"。

**确认语义**：调用投递服务默认只返回预览，不发请求、不写审计；必须带确认参数才会发送。审计只记录目标名称、策略摘要哈希、时间范围、事件数与事件 ID 列表，不记录载荷、URL 或密钥。

**删除边界**：删除本地事件不会改写历史审计；审计不含载荷，因此无需联动删除。已经发送到外部的数据无法回收，删除本机数据也不会影响接收方留存的副本。

**回滚**：卸载集成后 `user_version` 仍停在 2，`deliveries` 表留在库中；回滚到旧版本前应确认 `events` 表完好，重新安装时迁移使用 `IF NOT EXISTS`，不会因表已存在而失败。

OpenHealthRouter 不提供医疗诊断；隐私控制也不能替代设备、HA 主机、备份介质和目标服务的整体安全管理。
